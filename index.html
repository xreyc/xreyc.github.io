System design

Architecture I design & ship

Two representative production patterns — an event-driven serverless pipeline on AWS, and a containerized Go microservices platform on Kubernetes — showing how I keep systems reliable, secure, and observable.

Event-driven payment & receipt processing

ARCH-01 · AWS

A production-style AWS flow for receiving a payment: the command Lambda records a DynamoDB key reference and lands the raw payload in S3 as JSON, and the S3 object event triggers SNS fan-out into two independent queues — a receipt queue whose worker renders the PDF artifact, and an analytics queue whose loader Lambda copies events into Redshift — keeping rendering and analytics decoupled, and the whole path observable and replayable.

  • ReliableIdempotent commands, durable queues, DLQ redrive, and traceable retries.
  • SecureWAF, Cognito, scoped IAM, KMS encryption, and signed receipt access.
  • ObservableCloudWatch alarms, X-Ray traces, correlation IDs, and audit events.

Go microservices on Kubernetes

ARCH-02 · K8S

A containerized service platform with Go services, internal gRPC, asynchronous RabbitMQ workflows, Redis coordination, Postgres persistence, and platform-level telemetry — laid out for safe deploys and production operations.

  • ScalableStateless Go pods, horizontal autoscaling, and service-owned data stores.
  • DecoupledgRPC for sync calls, RabbitMQ with a dead-letter queue for async work.
  • OperableCI/CD deploys, RBAC, network policy, and a full telemetry plane.
